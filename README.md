# Food Boom

Лендинг доставки еды, блог и админ-панель (роли, права, заказы, заявки, публикации).

## Запуск локально (полноценный режим: Node.js + SQLite)

```
npm install
npm start
```

Сайт: http://localhost:5000 — данные хранятся в `foodboom.db`, доступ общий для всех устройств.

Демо-доступы:

## Деплой на Vercel (статический режим)

Vercel размещает проект как статический сайт и не запускает `server.js` — его
функции (Express, SQLite) на этой площадке недоступны. Чтобы сайт работал,
`js/api-fallback.js` перехватывает запросы к `/api/*` и, если настоящий сервер
не ответил JSON, обрабатывает их в браузере: те же эндпоинты, форматы данных,
роли и права, данные хранятся в `localStorage`.

Что это значит на практике:

- каталог, корзина, оформление заказа, форма обратной связи, вход, блог и
  админка работают сразу после загрузки страницы;
- заказы, заявки, публикации и пользователи сохраняются **только в том
  браузере**, где их создали (в админке показывается плашка «Демо-режим»);
- в админку можно войти теми же демо-учётками, что и локально;
- сбросить демо-данные: выполнить `FB.resetDemoData()` в консоли браузера и
  обновить страницу.

Если нужны общие данные для всех посетителей (настоящие заказы в админке),
нужен серверный хостинг с Node.js (VPS, Render, Railway) либо облачная БД —
тогда `server.js` используется как есть, а резервный режим не включается.

На localhost запросы идут в Express и ничего не подменяется.
